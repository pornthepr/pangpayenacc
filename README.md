# บันทึกรายรับรายจ่ายครอบครัว

เว็บแอป PWA (Next.js + Supabase) สำหรับสมาชิกครอบครัว (golf/gap/group/mom) บันทึกรายรับ-รายจ่าย-โอนระหว่างบัญชีร่วมกัน ดูรายละเอียดเต็มใน [`docs/`](./docs).

## เริ่มต้นใช้งาน (เฟส 0)

### 1. สร้างโปรเจกต์ Supabase

สร้างโปรเจกต์ใหม่ที่ [supabase.com](https://supabase.com), จากนั้นในหน้า **Project Settings > API Keys** คัดลอก Project URL, publishable key และ secret key

### 2. ตั้งค่า environment variables

คัดลอก `.env.example` เป็น `.env.local` แล้วกรอกค่าที่ได้จากข้อ 1:

```bash
cp .env.example .env.local
```

### 3. ติดตั้ง dependencies และรัน migration

```bash
pnpm install
pnpm supabase link --project-ref <your-project-ref>
pnpm supabase db push
```

คำสั่งนี้จะสร้างตารางทั้งหมด (profiles, accounts, categories, transactions, attachments, audit_logs), เปิด RLS, สร้าง trigger และ seed หมวดหมู่ตั้งต้น

### 4. สร้างผู้ใช้ 3 คน (golf/gap/group)

```bash
pnpm seed:users
```

รันครั้งเดียวตอนติดตั้ง (รันซ้ำได้ ผู้ใช้ที่มีอยู่แล้วจะถูกข้าม) รหัสผ่านเริ่มต้นคือ `golf1234` / `gap1234` / `group1234` / `111111` (mom) เว้นแต่ตั้งค่า `SEED_PASSWORD_GOLF` / `SEED_PASSWORD_GAP` / `SEED_PASSWORD_GROUP` / `SEED_PASSWORD_MOM` ไว้ใน `.env.local`

ถ้ามีคนลืมรหัสผ่าน ให้รีเซ็ตกลับเป็นค่าเริ่มต้นด้วย:

```bash
pnpm reset:password golf
```

### 5. รันเว็บแอป

```bash
pnpm dev
```

เปิด [http://localhost:3000](http://localhost:3000) แล้ว login ด้วย golf/gap/group

## Deploy ขึ้น Vercel

ตั้ง environment variables ใน Vercel project settings:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- `INTERNAL_EMAIL_DOMAIN` (ถ้าไม่ตั้ง จะ default เป็น `family.local`)

**ห้ามตั้ง** `SUPABASE_SECRET_KEY` ใน Vercel — ใช้เฉพาะรัน `seed:users`/`reset:password` ในเครื่องเท่านั้น

## ทดสอบ

```bash
pnpm test          # Vitest — ฟังก์ชัน logic ล้วน (validation, bucketing, period math)
pnpm test:e2e       # Playwright — flow หลักบนจอมือถือ (login → บันทึกรายจ่าย → ลบ)
```

**⚠️ โปรเจกต์นี้ไม่มี Supabase project แยกสำหรับทดสอบ** — `pnpm test:e2e` รันกับฐานข้อมูลที่ `.env.local` ชี้ไปจริงๆ ถ้านั่นคือฐานข้อมูลที่ครอบครัวใช้งานจริงอยู่ ให้รู้ไว้ว่า test จะสร้าง/ลบเฉพาะบัญชีและรายการที่ขึ้นต้นด้วย `E2E_TEST` เท่านั้น (ดูcleanup scope ใน `e2e/main-flow.spec.ts`) ไม่แตะข้อมูลอื่น แต่ถ้าจะปลอดภัย 100% แนะนำสร้าง Supabase project แยกไว้สำหรับทดสอบโดยเฉพาะ แล้วชี้ `E2E_BASE_URL`/`.env.local` ไปที่นั่นแทน

**บั๊กที่เจอและแก้ระหว่างทดสอบจริง:** (1) `note` ที่เป็น `null` (ไม่ได้กรอก) หลุดผ่าน Zod `.optional()` ไม่ได้เพราะ `null` ≠ `undefined` — แก้ด้วย `|| undefined` (2) soft delete (set `deleted_at`) ชน RLS policy เพราะ Postgres เช็ค SELECT policy กับค่าใหม่ของแถวตอน UPDATE ... RETURNING แก้ด้วย RPC `soft_delete_transaction` แบบ `security definer`

**บั๊กที่เจอและแก้ระหว่างทดสอบจริง (เฟส 3):** คำนวณขอบเขตเดือน/วันด้วย `new Date(y,m,d).toISOString().slice(0,10)` ผิดพลาดเมื่อเซิร์ฟเวอร์รันในโซนเวลาที่เร็วกว่า UTC (เครื่อง dev อยู่ Asia/Bangkok +7 แต่ Vercel รัน UTC) ทำให้วันที่เลื่อนข้ามเดือนได้ — เจอจริงตอนทดสอบ "เดือนนี้" ดึงข้อมูลเดือนก่อนมาแสดงแทน แก้โดยคำนวณปี/เดือน/วันด้วยเลขจำนวนเต็มล้วน (ไม่ผ่าน Date object + toISOString) ใน `lib/format/date.ts` ให้ตรงกับ Asia/Bangkok เสมอตามที่ requirement กำหนด

- [x] ส่งออก CSV ตามตัวกรองที่เลือกในหน้ารายการ (UTF-8 + BOM เปิดใน Excel ได้ภาษาไทยไม่เพี้ยน) — ทดสอบจริงแล้ว
- [x] Realtime: รายการใหม่จากคนอื่นขึ้นในหน้ารายการทันทีโดยไม่ต้องรีเฟรช — ทดสอบจริงด้วย 2 session พร้อมกัน
- [x] PWA: manifest + ไอคอน (192/512/maskable) + apple touch icon, ติดตั้งลงหน้าจอโฮมได้, มี service worker แบบเบา (cache หน้าที่เคยเปิดไว้ดูตอนเน็ตหลุด)
- [x] Dark mode: ตรวจทุกหน้าหลักแล้ว คอนทราสต์และสีผ่านหมด ไม่ต้องแก้อะไรเพิ่ม
- [x] Vitest (21 tests: bucketing, period math, validation schema, number formatting) + Playwright (flow หลัก: login → บันทึกรายจ่าย → เห็นในรายการ → ลบ) — รันผ่านจริงทั้งคู่

**บั๊กที่เจอและแก้ระหว่างทดสอบจริง (เฟส 4):**
1. **Proxy matcher พลาด `sw.js`** — service worker โดน proxy เด้งไป `/login` ทำให้ลงทะเบียนไม่ได้เลยสำหรับคนที่ยังไม่ login แก้ด้วยการเพิ่ม `sw.js` เข้า matcher exclusion
2. **Realtime ไม่ส่ง event มาที่ฝั่ง browser** — effect สร้าง channel ชื่อคงที่ (`"transactions-list"`), React dev-mode double-invoke effect ทำให้ channel ตัวแรกถูก cleanup หลัง subscribe ของตัวที่สองไปแล้ว (ชื่อชนกัน ไลบรารีปิดช่องที่ถูกต้องไปโดยไม่ตั้งใจ) แก้ด้วยการสุ่มชื่อ channel ใหม่ **ภายใน** effect callback ทุกครั้ง (ไม่ใช่ใน `useRef` ซึ่งค่าเดิมจะถูกใช้ซ้ำในการเรียกครั้งที่สอง)
3. **ข้อมูลจริงกับข้อมูลทดสอบอยู่ฐานเดียวกัน** — ระหว่างทดสอบพบว่ามีคนเริ่มใช้แอปจริงบันทึกรายการจริงคู่ขนานกับที่ผมทดสอบอยู่ ปรับทุก cleanup script ให้ลบเฉพาะแถวที่ตั้งชื่อ/note ขึ้นต้นด้วย `TEST-`/`ZZTEST`/`E2E_TEST` เท่านั้น ไม่มีการลบแบบกวาดทั้งตารางอีกเลยหลังจากจุดนี้

## การปรับแก้ตามคำขอ (หลังเฟส 4)

- [x] **หน้าแรก**: เดือนแรกสุด (เดือนที่มีรายการเก่าที่สุด) แสดง "ยอดเริ่มต้น", เดือนถัดมาแสดง "ยกยอดจากเดือนก่อน" แล้วค่อยตามด้วยรับ/จ่าย/คงเหลือ โดย **คงเหลือ = ยกยอด + รับ − จ่าย** (ยอดรวมทุกบัญชีจริง ไม่ใช่แค่ยอดสุทธิของเดือนนั้น) ปุ่มเดือนก่อนหน้าจะปิดเมื่อถึงเดือนแรกสุด — ระหว่างทดสอบเจอบั๊ก text ของจำนวนเงินยาวๆ ตัดขึ้นบรรทัดใหม่กลางคำในช่อง 3 คอลัมน์ แก้ด้วย `whitespace-nowrap` + ลดขนาดตัวอักษร และพบว่า "จ่าย" เดิมไม่ได้ใส่เครื่องหมาย `-` เลยด้วยซ้ำ (บั๊กเก่าจากเฟส 3) แก้ไปพร้อมกัน
- [x] **ประวัติการแก้ไข**: จำกัดให้ user **gap คนเดียว** เห็นได้ (คนอื่นแก้ไขรายการได้ปกติ แค่ไม่เห็นหน้าประวัติ) — บังคับจริงที่ชั้น RLS (`audit_logs` select policy เช็ค username='gap') ไม่ใช่แค่ซ่อนที่ UI
- [x] **เพิ่มผู้ใช้ "แม่ไก่"** (username `mom`) รหัสผ่านเริ่มต้น `111111` — สร้างจริงใน Supabase Auth แล้ว
- [x] **หน้ารายงาน**: ชิป "เดือนนี้"/"เดือนก่อน" แสดงชื่อเดือนจริง (เช่น "ตุลาคม 2569"/"กันยายน 2569") แทนข้อความทั่วไป, เพิ่มกราฟเส้น "แนวโน้มรายเดือน" ที่ตอบสนองกับทุกตัวเลือกช่วงเวลา (ใช้ `rpc_monthly_summary` เดิม)
- [x] **หน้ารายงาน**: เอาปุ่มสลับรายรับ/รายจ่ายออก แสดงทั้งสองพร้อมกันเสมอ เปลี่ยนจากกราฟแท่งเป็น **กราฟพาย** ตามที่ขอ (มี legend + % กำกับเสมอ ไม่พึ่งสีอย่างเดียว)
